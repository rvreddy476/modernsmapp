# Cloud agent brief — REELS production-readiness audit (TikTok reference)

Read `docs/production-readiness/agents/00_COMMON_RULES.md` first. Audit only; no code changes. Output: `docs/production-readiness/REELS_AUDIT.md` + `REELS_AUDIT_LOG.md` on branch `audit/reels-production-readiness`.

## Scope checklist (every item becomes a row in your feature matrix)
**Playback:** full-screen vertical player; infinite swipe up/down; autoplay on appear / pause on scroll-out / resume context; mute (sticky once unmuted), full-screen, speed; ABR (hls.js, quality selection); smart prefetch of next videos; playback recovery after network failure.
**Upload & publishing:** short-form upload within the 5-minute cap (15/30/60 s presets as UI); resumable upload; transcoding to multi-bitrate HLS (360p/480p/720p/1080p as configured); thumbnail auto + user-selectable cover frame; drafts, scheduled, published, archived/deleted states; title, hashtags, mentions, auto captions.
**Engagement:** likes, comments, shares, saves with instant and persisted counts; mini-profile and follow from the reel; sound-based trending, trending creators, For You ranking; watch-time/completion/drop-off events; idempotent engagement tracking (no double counts).
**Quality & moderation:** format/codec/duration/resolution validation; automated moderation (Rekognition), copyright detection (fingerprint/match), spam; creator controls: disable comments, restrict downloads/offline copies, age-gate.

## Things to verify specifically
- Every playback path goes S3 → CloudFront with signed access; no Go byte proxy for segments.
- Prefetch/preload of next reels exists on web (hls.js) and Android (PlayerPool) and is bounded.
- Engagement double-count protection (react idempotency, analytics `ingest_receipts`, view cap).
- Transcode retries, poison quarantine, stall sweeper recovery, user-facing failure state.
- Moderation runs before publish or flags after; what a creator sees; age-gate enforcement on feed and direct links.
- Trending sounds actually ranked by use and velocity; FYP signals beyond recency.

## Targets for the scaling assessment
**500K+ concurrent viewers, sub-500 ms feed generation, 99.9% uptime.** Assess CDN offload ratio (segments must never hit origin services), HLS segment size/count, transcode throughput (videos/hour per worker, queue depth), Scylla engagement write rates, Redis trending/HLL memory, analytics ingest throughput (events/s per pod). Propose load tests: k6 feed swipe scenario (N users × 1 req/3 s), analytics ingest burst, transcode backlog drain test, CloudFront cache-hit validation.

## E2E journeys for your matrix
- Upload a 30-second reel → process → publish → appears in the reels feed.
- Swipe through the feed; autoplay, pause, resume without stalls.
- Like, comment, share, save → counts update instantly and persist after reload.
- Use one sound in several reels → sound page and trending reflect it.
- Follow a creator → their reels in following and FYP.
- Disable comments on a reel → others cannot comment (API and UI).
- Playback on throttled networks (2G/4G/Wi-Fi) → ABR quality switching (browser devtools throttling / Media3 bandwidth meter).
- Concurrent likes and views → exact counts; views counted once per the rules.
- Private/deleted/age-gated reels not playable by unauthorised users (direct media URLs included).
